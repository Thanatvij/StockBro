# Decision log

รูปแบบ: รหัส · วันที่ · ตัดสินใจอะไร · เหตุผล · ทางเลือกที่ไม่เลือก

## D-01 · 17 พ.ย. 2569 · แยกเป็นโปรเจกต์ใหม่ ไม่แก้ ARGUS
ARGUS มี decision log/เทสต์เยอะและโดเมนต่างกัน (ภัยพิบัติ/ความมั่นคง) → ยืมแนวคิด (ingest→cluster→scoring→explainable) ไม่ยืมโค้ดภูมิศาสตร์

## D-02 · ชื่อ Kairos
ดูชื่อ Moonwatch/StockLab/SignalLab/TrueTick/2130 แล้ว Thanat เลือก καιρός (กรีก = "จังหวะเวลาที่ใช่" และ "สภาพอากาศ" เชื่อมกลับ ARGUS) ใช้ตัวกรีกเฉพาะหน้าจอ ชื่อโค้ดเป็น ASCII เพราะตัวอักษรไม่ใช่ ASCII พัง tooling

## D-03 · จุดขายคือ "ข่าวจริงไหม/เก่าไหม" + accuracy tracker ไม่ใช่ความเร็ว
เคส SPCX: ข่าวจริงแต่เก่าเกือบ 2 ปี ราคา price-in แล้ว ระบบ batch รายวันแข่งความเร็วกับ bot ไม่ได้ สูตร Pivot ใครก็คำนวณได้ (TradingView ฟรี) → ความต่างอยู่ที่การวัดผลย้อนหลัง/forward-test พร้อม baseline

## D-04 · ไม่ใช้ LLM / API key ในเฟส 1
Thanat ไม่ต้องการให้ระบบใช้ API key ของตัวเอง (เปลืองโควตา) → ข้อความไทยมาจาก template, คะแนนข่าวมาจากกฎ, ทิศทางข่าวมาจาก keyword ในพาดหัว (ระบุชัดว่าไม่ใช่ความเห็นระบบ) ถ้าอนาคตเพิ่ม LLM ให้ใช้สรุปข้อความเท่านั้น ไม่แตะตัวเลข

## D-05 · ใช้งานส่วนตัว/กลุ่มเพื่อน ไม่เปิดสาธารณะ
การบอกจุดซื้อ-ขายเฉพาะรายตัวแก่สาธารณะอาจเข้าข่ายให้คำแนะนำการลงทุนที่ต้องมีใบอนุญาต ก.ล.ต. (ยังไม่ได้ตรวจสอบกับ ก.ล.ต.) จึงใช้ถ้อยคำเชิงข้อมูล + disclaimer; repo ตั้งเป็น **private** เพราะมีพอร์ตส่วนตัว

## D-06 · แหล่งข้อมูล: Yahoo + SEC EDGAR (ฟรี ไม่ต้อง key)
Bloomberg/Reuters/CNBC ติด paywall และ ToS ห้าม scrape; ราคา real-time ไม่จำเป็นสำหรับ brief ก่อนตลาดเปิด ใช้ราคาปิดรายวัน (Yahoo เป็น endpoint ไม่ทางการ → มี cache สำรอง) Finnhub เก็บไว้เป็นทางเลือกถ้า Yahoo พัง

## D-07 · เฟส 1 รันบน Mac / ส่งเมลแบบรายวัน; Backend เฟส 2 = Better Auth + Neon + Vercel
ตรวจจาก Vercel ของ propmap-bangkok แล้วใช้ Better Auth + Postgres (Neon) → ใช้ชุดเดียวกัน ไม่ต้องเรียนระบบใหม่ ไม่เลือก Supabase เพราะต้องเรียน auth ใหม่ SQLite ในเฟส 1 เขียน schema ให้ย้ายไป Postgres ได้ การแจ้งเตือนอีเมล: แบบ brief วันละครั้งผ่าน GitHub Actions (cron 19:30 น.) ก่อน; แบบแจ้งเตือนราคาระหว่างตลาดเปิดต้องมีเซิร์ฟเวอร์รันตลอด (ทีหลัง)

## D-08 · ธีมมืด, ไฟล์ HTML เดียว, stdlib เท่านั้น (ส่วน "HTML เดียว" ถูกแทนด้วย D-10/D-15)
Thanat ต้องการธีมมืด; ไม่มี build step/dependency เพื่อให้รันได้ทุกเครื่องและแก้ง่าย (Thanat ไม่ชอบงาน web หนัก)

## D-09 · เก็บสัญญาณตั้งแต่วันแรก
forward-test ย้อนเก็บไม่ได้ → `run.py` (โหมดจริง) บันทึกทุกครั้ง ข้อมูล `--offline` ไม่ถูกบันทึกเพื่อไม่ให้ปนข้อมูลจำลอง

## D-10 · เว็บหลายหน้า ภาษาเพื่อน (แทนหน้าเดียวของ v0.1)
Thanat: v0.1 ดูเหมือนหน้ากระดาษ กดไม่ได้ ไม่เห็นข่าว ศัพท์ไม่เข้าใจ ต้องการ "เพื่อนนักลงทุน" ไม่ใช่เว็บสรุปราคา → หลายหน้า ข่าวแสดงเปิดเต็ม พร้อมลิงก์ต้นฉบับ ทุกศัพท์มี tooltip/หน้า glossary ถ้อยคำเพื่อนมาจากแม่แบบ+ตัวเลขจริง (`friend.py`) ไม่แนะนำซื้อ/ขายตรงๆ (ตาม D-04/D-05) ยังเป็นไฟล์ static ไม่ต้องมีเซิร์ฟเวอร์ (แก้ D-08: ไม่ใช่ไฟล์เดียวแล้ว แต่ยัง stdlib เท่านั้น)

## D-11 · แปลข่าวด้วย API แปลภาษา ไม่ใช้ LLM
แค่ต้องการอ่านพาดหัวเป็นไทย → ใช้ API แปล (MyMemory ไม่ต้องมี key ฟรี 5,000 ตัวอักษร/วัน) เพราะไม่แต่งเนื้อหาเพิ่ม ถูกกว่า และไม่ใช้โควตา Claude ปริมาณใช้จริง ~4k ตัวอักษร/วัน ติดป้าย "แปลโดยเครื่อง" เสมอ + เก็บต้นฉบับ+ลิงก์ ถ้าแปลไม่ได้แสดงอังกฤษ ทางเลือกอัปเกรด: Azure (2M/เดือน), Google (500k), DeepL (500k, ยังไม่ยืนยันภาษาไทย) การ "วิเคราะห์ข่าวเป็นภาษาเพื่อน" ยังไม่ทำ (ต้องใช้ LLM) เว้นช่องไว้

## D-12 · กรองข่าวด้วยกฎ ticker/ชื่อบริษัท และลดการเตือนซ้ำซาก
Yahoo RSS มีข่าวบริษัทอื่นปน → เก็บเฉพาะพาดหัวที่มี ticker (case-sensitive) หรือ alias ที่ระบุ ผลคือบางข่าวที่เกี่ยวจริงแต่ไม่เอ่ยชื่ออาจหลุด (ยอมรับ ดีกว่าข่าวขยะ) "ใกล้แนวรับ" เดิมขึ้นทุกตัวเพราะมีระดับให้เลือกหลายอัน → เกณฑ์ 1.5% และเตือนไม่เกิน 2 ตัว

## D-13 · ชื่อที่แสดง = StockBro (Investment Bro)
Thanat เปลี่ยนจาก Kairos/καιρός เป็น StockBro เพราะอยากได้โทน "เพื่อนคุยกับเพื่อน" เปลี่ยนเฉพาะชื่อบนหน้าเว็บ (โลโก้/title/footer) โลโก้ = ตัวอักษร καιρός (เป็นเครื่องหมาย) + คำว่า StockBro; ถ้อยคำในเว็บเป็นโทน "Bro" พูดกับผู้ใช้ตรงๆ (นาย/Bro) ไม่ใช่บุรุษที่สาม ชื่อแพ็กเกจโค้ด `stockbro_engine` โฟลเดอร์ และ repo KAIROS คงเดิมเพื่อไม่ให้ import/พาธพัง

## ค่าตั้งต้นที่ต้องทบทวนหลังมีข้อมูลจริง
horizon 5 วัน · target/stop ±2% · เกณฑ์ใกล้แนวรับ 1.5% (จำกัด 2 ตัว) · alias ข่าว · ราคาขยับแรง 3% · กระจุกตัว 35% · เกณฑ์ข่าวเก่า 7 วัน · Jaccard 0.5 · น้ำหนักหมวดข่าว

## D-14 · repo เป็น public
Thanat ตัดสินใจเปิด public เพื่อใช้เป็นผลงานพอร์ตโฟลิโอ แก้ D-05 เฉพาะเรื่อง repo (ส่วน "ไม่เปิดเว็บให้คนทั่วไปใช้" ยังคงเดิม) เพราะ repo public → `config/portfolio.json` เป็นพอร์ตตัวอย่างสมมติเท่านั้น พอร์ตจริงทำหลังมีระบบล็อกอิน (เก็บใน DB ไม่ใช่ใน repo) ห้ามเอาพอร์ตของเพื่อน/ข้อมูลลับขึ้น repo

## D-15 · แยกหน้าเว็บเป็น index.html + style.css + app.js, Python ออก JSON, เว็บแค่แสดงผล
Thanat ไม่ชอบโค้ดที่ Python ปั้น HTML เป็นสตริง และอนุญาตให้เลือกเทคโนโลยีใดก็ได้ (MERN/React/Vue/FastAPI ฯลฯ) ตัดสินใจ: **เฟสนี้ = HTML/CSS/JS ล้วน (vanilla ES modules-free, ไม่มี build)** แยกไฟล์ชัดเจน, หลายหน้าจริง (6 ไฟล์ .html ใช้ style.css/app.js ร่วมกัน), อ่าน `data/report.json` ที่ Python สร้าง
เหตุผลที่ยังไม่ใช้ React/Vue/MERN ตอนนี้: (1) ตรรกะทั้งหมดเป็น Python/data science ซึ่งเป็นจุดแข็งและจุดขายของงานนี้ เว็บเป็นแค่ชั้นแสดงผล (2) ยังไม่มี user/DB/API สด ไม่มีอะไรให้ framework ช่วยจริง (3) ไม่มี build → deploy GitHub Pages/Vercel ได้ทันที และแก้ได้ด้วยตา (4) Thanat ไม่ชอบงาน web หนัก
**เฟส 2 (login + พอร์ตต่อคน):** ย้ายเปลือกเว็บเป็น **Next.js + Better Auth + Neon Postgres บน Vercel** (ชุดเดียวกับ propmap-bangkok ที่ Thanat มีอยู่แล้ว) ส่วน engine Python เดิมเป็นตัวสร้าง JSON/หรือหุ้มเป็น FastAPI ตอนมีฐานข้อมูล ไม่ต้องเขียนตรรกะใหม่ — หน้าเว็บปัจจุบันถูกออกแบบให้ย้ายง่าย (รูปแบบ JSON คงที่)
เปิดเว็บต้องผ่าน server (fetch JSON ผ่าน file:// ไม่ได้) ข้อมูลจำลองเขียนเป็น `report.sample.json` แยกจากของจริง เว็บ fallback ไปไฟล์ตัวอย่างพร้อมแบนเนอร์ถ้ายังไม่มี report.json
